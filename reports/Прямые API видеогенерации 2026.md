# Прямые API пока не вытесняют свой LTX

На октябрь 2026 года живых first-party API для видеогенерации больше дюжины. Ни один не закрывает весь бриф (6 с, 9:16 не ниже 1080×1920, image-to-video, negative prompt, без текста в кадре) дешевле и с тем же контролем, что self-hosted LTX-2.5 dev на Runpod: **$0.40–0.50 за ролик, около $4–5 за выпуск**. Без компромиссов по параметрам бриф выполняют только два хостинговых варианта: **PixVerse V6** (нативные 6 с, 1080p, `negative_prompt`, `seed`; около $0.54 за ролик) и **Alibaba Wan 2.6/2.7** (`negative_prompt`, `seed`, 2–15 с, регион US-Virginia; от $0.23 до $0.90 за ролик). У Google Veo 3.1 лучший набор возможностей, но 1080p доступен только при длительности 8 с, а `negativePrompt` официально описан только на Vertex. Через ключ Gemini API ролик Veo 3.1 Fast обойдётся примерно в $0.96: оплачиваются 8 с, потом ролик обрезается до 6. Рынок заметно сузился: **OpenAI закрыл Sora 2 API 24 сентября 2026 года**, а **BytePlus (Seedance) официально недоступен в США** и вдобавок отклоняет кадры с фотореалистичными лицами. Кроме того, ни один хостинговый API не даёт задать CFG и число шагов, а hosted LTX вероятнее всего работает на distilled-чекпойнте. Поэтому для требования владельца «полная модель, обычный CFG» своя установка остаётся единственным вариантом с полным контролем. Рекомендация: оставить LTX основным путём, PixVerse V6 подключить как резервный хостинговый вариант, а на ключе Gemini слепо сравнить качество с Veo 3.1 Fast/Lite на тех же первых кадрах.

## Карта рынка: Sora закрыта, Seedance закрыт для США, остальные работают по схеме submit→poll

Важнее всего две потери. OpenAI пишет прямо: «The Sora 2 models and Videos API were shut down on September 24, 2026… No one-to-one replacement API is available» ([OpenAI: Video generation](https://platform.openai.com/docs/guides/video-generation)). В списке устаревших моделей рекомендованная замена обозначена прочерком ([OpenAI Deprecations](https://platform.openai.com/docs/deprecations)). Для этого проекта потеря невелика: Sora и раньше отклоняла входные картинки с человеческими лицами. ByteDance по-прежнему развивает Seedance 2.0/2.5, но в анонсах обеих версий есть оговорка «BytePlus is not available in the United States» ([BytePlus blog, Seedance 2.5](https://www.byteplus.com/en/blog/dreamina-seedance2-5)), и в официальном списке стран США нет ([BytePlus: International Availability](https://docs.byteplus.com/en/docs/ModelArk/availability)). Китайский Volcengine требует местной верификации личности. Получается, что Seedance доступен американскому разработчику только через перепродавцов (Runway, Higgsfield, Pika API Club), а это уже не first-party.

У Google теперь два семейства. **Veo 3.1** выходит в трёх уровнях (Standard, Fast, Lite) и в Gemini API до сих пор помечен как Preview. **Gemini Omni Flash** (`gemini-omni-1.1-flash`) Google сам называет моделью по умолчанию для видео ([Gemini API: Video generation](https://ai.google.dev/gemini-api/docs/video)). «Veo 4» ни в одном официальном документе нет. У Luma остался единственный видеоэндпоинт — новый Agents API с моделью `ray-3.2`. Ray 2 и Ray 3 выводятся из эксплуатации, а старый Dream Machine API объявлен legacy ([Luma Migration guide](https://docs.agents.lumalabs.ai/guides/videos/migration/)). У Pika первый собственный API появился 5 августа 2026 года: это Pika API Club с Pika 2.5 и сотней перепродаваемых моделей ([Pika blog](https://pika.art/blog/pika-api-club)). Higgsfield в сентябре 2026 года открыл self-serve API, но по сути это агрегатор: 67 видеопозиций в 22 семействах, из них собственные только Genjutsu, Cinema Studio и DoP ([Higgsfield Video API](https://docs.higgsfield.ai/docs/models/video-generation)). Lightricks перенёс API на `api.ltx.io`. Синхронные V1-эндпоинты перестанут работать **после 26 октября 2026 года**, асинхронный V2 продолжит работу ([LTX API Changelog](https://docs.ltx.io/api-changelog)).

Технически все провайдеры работают одинаково: задача ставится POST-запросом, потом её статус опрашивается, потом готовый MP4 скачивается по временной ссылке. Различаются способ авторизации, наличие вебхука и срок хранения результата. Срок хранения важен: файлы нужно забирать сразу, это ложится на существующую схему `WORKDIR` → `cleanup_temp_files`.

## Шесть секунд, 1080×1920 и negative prompt одновременно дают только PixVerse и Wan

Почти везде портретный кадр получается одинаково: пропорции выхода берутся с входной картинки. У xAI это сказано прямо: «Image-to-video output always matches the input image's aspect ratio; `aspect_ratio` is ignored» ([xAI Video Generation](https://docs.x.ai/developers/model-capabilities/video/generation)). Документация не подтверждает заметку в CLAUDE.md о том, что xAI растягивает кадр, если передать `aspect_ratio`. Параметр просто игнорируется, хотя не передавать его по-прежнему безопаснее. Так же устроены PixVerse (у i2v нет `aspect_ratio`), Wan («The current API does not support setting the video aspect ratio directly», ширина и высота кратны 16), Hailuo, Kling 3.0 и Seedance 2.5 (режим `adaptive` обязателен). Значит, первый кадр нужно сразу готовить в 1080×1920. Точный размер выхода 1080×1920 документирован только у LTX API (строка `"1080x1920"`) и у Seedance 2.0/2.5. PixVerse возвращает `outputWidth`/`outputHeight` в статусе задачи, у остальных размер нужно проверять через ffprobe на первом ролике ([LTX-2.5](https://docs.ltx.io/models/ltx-2-5); [Volcengine Ark API](https://www.volcengine.com/docs/82379/1520757); [PixVerse status](https://docs.platform.pixverse.ai/get-video-generation-status-13016632e0)).

Отсеивают провайдеров в основном длительность и negative prompt. **Veo 3.1 поддерживает 4, 6 и 8 с, но 1080p и 4k «Must be "8"»** ([Gemini API: Veo 3.1](https://ai.google.dev/gemini-api/docs/veo)): шесть секунд в 1080p получаются только генерацией 8 с с последующей обрезкой. Luma Ray 3.2 умеет только 5 и 10 с, причём 10 с с `start_frame` запрещены ([Luma Video generation](https://docs.agents.lumalabs.ai/guides/videos/generation/)). Pika 2.5 даёт 5 или 10 с. Hailuo, наоборот, разрешает 1080P **только** при 6 с, то есть ровно под бриф ([MiniMax I2V](https://platform.minimax.io/docs/api-reference/video-generation-i2v)). Минимальная длительность LTX API тоже 6 с. Negative prompt есть у немногих. Его прямо отрицают Luma («Does the API support negative prompts? No» — [Luma FAQ](https://docs.agents.lumalabs.ai/guides/faq/)), Omni Flash («negative prompts are not supported» — [Gemini API: Omni](https://ai.google.dev/gemini-api/docs/omni)) и Seedance (в полном списке полей его нет). У xAI, LTX API, Runway Gen-4.5, Hailuo и Vidu такого параметра нет в документации. У Veo `negativePrompt` описан только на Vertex ([Vertex: image-to-video](https://cloud.google.com/vertex-ai/generative-ai/docs/video/generate-videos-from-an-image)), а в текущей таблице параметров Gemini API его нет. Принимает ли Gemini API этот параметр на деле, можно выяснить только тестовым вызовом.

Из этой матрицы видно главное. Кроме своей установки, нативные 6 с, 1080p, image-to-video, `negative_prompt` и `seed` одновременно дают только **PixVerse V6/C1** и **Wan 2.6/2.7**. Vertex Veo закрывает требования с поправкой на 8 с и обрезку. Для требования «без текста в кадре» есть отдельные риски. Omni Flash, по словам Google, хорошо рисует читаемый текст, и это прямо противоречит задаче. У Wan есть параметр `watermark`, его нужно явно выставлять в `false`. SynthID у Google невидим и кадр не портит.

Отдельно стоит сказать о hosted LTX. API не принимает negative prompt, seed, guidance и steps. На странице LTX-2.5 упоминается «a better distilled model», но какой чекпойнт стоит за Fast и Pro, не раскрыто ([LTX-2.5](https://docs.ltx.io/models/ltx-2-5)). Требование владельца из HANDOFF.md («не distilled, не INT8, обычный CFG, не ниже 1080×1920») через этот API проверить нельзя. Поэтому `ltx-2-3-fast` за $0.36 нельзя считать заменой своей установки, даже при более низкой цене.

Третий: перепродавцы обычно дороже первоисточника. PixVerse V6 у Higgsfield стоит от $0.115 за секунду против примерно $0.09 напрямую, Grok 1.5 через Runway стоит около $1.75 против $1.51 у xAI ([Higgsfield API blog](https://higgsfield.ai/blog/higgsfield-api)). Платить наценку агрегатору имеет смысл только ради одного ключа ко многим моделям.

Пропускная способность ограничивает сильнее, чем цена. Новый платный проект Gemini API (Tier 1) упирается в лимит **$10 расходов за скользящие 10 минут**. Этого хватает примерно на 10 роликов Veo 3.1 Fast, то есть на один выпуск за окно, или на три ролика Standard ([Gemini API rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)). У LTX API по умолчанию 2 параллельные задачи ([LTX Rate Limits](https://docs.ltx.io/rate-limits)), у Runway на Tier 1 одна-две ([Runway Usage Tiers](https://docs.dev.runwayml.com/usage/tiers/)). У Wan 5 параллельных задач, у PixVerse даже на бесплатном членстве 3, у Higgsfield 20. При десяти роликах на выпуск ни одно из этих ограничений не блокирует работу, но на Gemini Tier 1 повторные дубли уже не помещаются в то же окно.

## Из США доступны почти все, но модерация бьёт по сюжету

Для частного разработчика из США доступ почти везде одинаковый: самостоятельная регистрация, предоплата картой, без проверки бизнеса и KYC. Gemini API официально доступен в США с 18 лет. Veo и Omni работают только на платном уровне, бесплатного нет ([Gemini API regions](https://ai.google.dev/gemini-api/docs/available-regions); [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing)). Минимальное пополнение у Runway и PixVerse — $10. У Luma и Higgsfield минимума нет, Pika берёт $10 в месяц и возвращает их кредитом в первом месяце ([Runway Setup](https://docs.dev.runwayml.com/guides/setup/); [Luma FAQ](https://docs.agents.lumalabs.ai/guides/faq/); [dev.pika.art](https://dev.pika.art/)). Заметки по Kling, MiniMax и Vidu изначально писались для пользователя из Центральной Азии. Для США в официальных выдержках ни у одного из трёх нет запрета по стране. Все три выставляют счета в долларах, а Vidu прямо добавляет «applicable sales tax», что похоже на расчёт на американских клиентов ([Vidu Pricing](https://platform.vidu.com/docs/pricing)). Реальный барьер у Kling финансовый, а не географический: по сторонним данным минимальный пакет стоит $700 и сгорает через 180 дней ([Kling API Pricing](https://kling.ai/dev/pricing)). MiniMax работает по pay-as-you-go без минимума. Явного списка разрешённых стран мы не нашли ни у одного из трёх, поэтому это вывод, а не подтверждённый факт.

Китайские провайдеры несут политический риск. Alibaba Model Studio формально доступен лучше всех: есть регион US-Virginia, индивидуальные аккаунты, оплата картами Visa, Mastercard и Amex, обязательная верификация только для ресурсов в материковом Китае ([Alibaba Cloud: Identity verification](https://www.alibabacloud.com/help/en/account/account-verification-overview)). Бесплатная квота действует только в Сингапуре ([Model Studio pricing](https://www.alibabacloud.com/help/en/model-studio/model-pricing)). При этом в июле 2026 года Минфин США допускал санкции против китайских лабораторий за дистилляцию, и Alibaba была в числе названных ([Vibranium Labs](https://vibraniumlabs.ai/blog/chinese-ai-models-sanctioned-whats-actually-happening)). Министерство коммерции КНР в те же недели обсуждало с Alibaba и ByteDance ограничение зарубежного доступа к лучшим моделям ([Reuters](https://www.reuters.com/world/beijing-is-looking-curbing-overseas-access-chinas-top-ai-models-sources-say-2026-07-07/)). Ни одна из этих мер не принята. Но строить единственный производственный путь на Wan рискованнее, чем на PixVerse (сингапурское юрлицо) или Google.

Для сюжета о кыргызах 1890-х важнее всего ограничения модерации, и они у провайдеров разные. Veo в режиме image-to-video принимает только `personGeneration: "allow_adult"` ([Gemini API: Veo 3.1](https://ai.google.dev/gemini-api/docs/veo)). Код безопасности Vertex «Child» отклоняет запросы с детьми, если не выставлен `allow_all`, а для image-to-video `allow_all` недоступен ([Vertex: Responsible AI for Veo](https://cloud.google.com/vertex-ai/generative-ai/docs/video/responsible-ai-and-usage-guidelines)). Значит, **кадры с детьми у юрты Veo отклонит**. Seedance 2.x не принимает изображения с реальными лицами, а сторонний тест показал отказ даже на сгенерированных ИИ фотореалистичных людях ([DataCamp](https://www.datacamp.com/tutorial/seedance-2-0-api-guide)). Luma блокирует «deepfakes of real people» и предупреждает о ложных срабатываниях на фото реальных людей ([Luma FAQ](https://docs.agents.lumalabs.ai/guides/faq/)). Поэтому первые кадры должны быть сгенерированы, а не взяты из архивных фотографий. Фильтр знаменитостей и «recognizable people» у Google и Luma настроен на узнаваемых лиц. Анонимные пастухи в национальной одежде под него попадать не должны, но никто из провайдеров отдельно об исторических или этнических сюжетах не пишет. Деньги за заблокированные ролики тоже возвращают по-разному: Google, Luma, Higgsfield и Wan за отклонённые генерации не берут, а Runway и xAI берут, причём Runway за частую модерацию может заблокировать аккаунт ([Runway Content Moderation](https://docs.dev.runwayml.com/api-details/moderation/); [xAI Pricing](https://docs.x.ai/developers/pricing)).

## Рекомендация: LTX остаётся основой, PixVerse становится резервом, Veo — эталоном для сравнения

Основным путём стоит оставить **self-hosted LTX-2.5 dev**. Это единственный вариант, где одновременно есть negative prompt, настраиваемый CFG и число шагов, гарантированно полная, не distilled модель и выход 1088×1920. По цене ($4–5 за выпуск) он не уступает хостинговым API с похожими параметрами. Слабые места у него операционные: холодный старт, засев venv, падения ComfyUI после серии заданий, необходимость H100 с 80 ГБ. Ни одна из найденных публичных моделей эти проблемы не убирает, не жертвуя контролем.

Резервным хостинговым провайдером для дней, когда Runpod недоступен или горит срок, стоит сделать **PixVerse V6**. Он закрывает бриф без компромиссов: `duration: 6`, `quality: "1080p"`, `negative_prompt` до 2048 символов (`text, captions, subtitles, letters, watermark, logo`), `seed`, `generate_audio_switch: false`. Стоит около $0.54 за ролик и $5.40 за выпуск, вход — $10 ([PixVerse V6](https://docs.platform.pixverse.ai/v6-2056814m0); [PixVerse Pricing](https://docs.platform.pixverse.ai/pricing-796039m0)). Скрипт строится по образцу `scripts/grok_video.py` и отличается тремя деталями: картинку нужно заранее загрузить, чтобы получить `img_id`, каждый запрос должен нести новый `Ai-trace-id` (повтор вернёт старый результат), а размер выхода проверяется по `outputWidth`/`outputHeight`. Дешёвой альтернативой с тем же набором параметров остаётся **Wan 2.6-i2v** в регионе US-Virginia: `negative_prompt`, `seed`, `watermark=false`, `prompt_extend=false`, чтобы переписывание не осовременивало костюмы, и пять параллельных задач ([Wan i2v API reference](https://www.alibabacloud.com/help/en/model-studio/image-to-video-api-reference)). Его стоит держать вторым номером из-за политического риска и того, что американские цены на 2.6 не опубликованы в найденных выдержках.

С ключом Gemini стоит провести слепое сравнение качества, а не переносить производство. Нужно взять 3–4 первых кадра из выпуска (обязательно без детей) и прогнать их через **Veo 3.1 Lite** ($0.64) и **Veo 3.1 Fast** ($0.96) в 1080p, 9:16, `durationSeconds: "8"`, с обрезкой до 6 с в FFmpeg. Заодно стоит проверить, примет ли Gemini API незадокументированный `negativePrompt`. Если не примет, запреты придётся переносить в основной промпт. Если Veo заметно выигрывает по реализму и историческим деталям, следующий шаг — Vertex: там `negativePrompt` описан официально, а ролик без звука стоит $0.40–0.80. Но Vertex требует OAuth и GCP-проект, а на странице модели указано «Pay-as-you-go: Not supported», и доступ для частного аккаунта нужно сначала проверить ([Vertex: Veo 3.1](https://cloud.google.com/vertex-ai/generative-ai/docs/models/veo/3-1-generate)). **Grok Imagine 1.5** уже подключён и оправдан для отдельных сцен, где LTX не справляется, но как основной путь он самый дорогой из нативных 1080p-вариантов ($1.51 за ролик) и без negative prompt.

Исключить стоит Sora (закрыта), Seedance (недоступен в США, отклоняет лица), Luma Ray 3.2 (5 с, нет negative prompt, $1.20 за ролик), собственные модели Runway (максимум 720×1280), прямой Kling (дорогой входной пакет и неподтверждённый negative prompt в новом API), Omni Flash (апскейл, склонность рисовать текст), а также Midjourney (API нет), Amazon Nova Reel (только 1280×720) и Adobe Firefly (фиксированные 5 с) ([AWS Nova](https://docs.aws.amazon.com/nova/latest/userguide/video-generation.html); [Midjourney Video](https://docs.midjourney.com/hc/en-us/articles/37460773864589-Video)). Ни одна заметка не оценивала визуальное качество и историческую достоверность моделей. Рекомендация опирается на параметры, цену и доступ, и окончательно выбор решит только сравнение на одних и тех же кадрах.

## Заключение

Главный сдвиг 2026 года в том, что прямые API стали дешёвыми, но управлять ими стало сложнее. Почти все провайдеры убрали CFG и шаги из публичных параметров, многие убрали negative prompt (Luma, Omni, Seedance, hosted LTX), а пропорции кадра теперь задаются входной картинкой. В результате качество ролика определяет в первую очередь первый кадр, а не параметры генератора. Конвейеру выгоднее вкладываться в чистый текстом 1080×1920 стартовый кадр без детей и архивных лиц, чем в подбор модели: такой кадр одинаково работает в LTX, PixVerse, Wan и Veo.

Второй вывод: выбор провайдера сейчас определяется в основном юрисдикцией и правилами модерации, а не ценой за секунду. Закрытие Sora, исключение США из BytePlus и возможные ограничения доступа к китайским моделям с обеих сторон показывают, что любой отдельный API может исчезнуть за полгода. Своя установка на открытых весах здесь служит страховкой от рисков поставщика, а один-два хостинговых провайдера с совместимыми параметрами (PixVerse и, если подтвердится качество, Veo) должны стоять рядом как заранее отлаженная замена, а не как будущая миграция.
